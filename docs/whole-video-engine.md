# 전체 영상 관찰 엔진

## 작업 기준
- 목표: 모바일 촬영/기존 영상 입력 → 영상 전체 관찰 → 근거가 부족한 부위 표시 → 보충 영상 누적 → 연출 기획 전달.
- 사용자: 제품을 손으로 돌려 촬영하는 모바일 사용자. 정면·회전 방향·속도 안내가 필요하다.
- 기준 자료: 기존 FRAME 코드, 사용자가 제공한 실제 안경케이스 영상(39.03초). 개인 영상은 배포 대상에서 제외한다.
- 변경 범위: 기본 `/capture`, 전체 영상 API/저장/관찰 기록, 기존 촬영 전용 데모, 기획에 누적 정보 전달. 기존 기획 요구사항 처리 기능은 유지한다.
- 완료 증거: 원본 프레임 수 대조, 실제 AI 판독, 모바일 Chromium/WebKit 조작, 예상 밖 녹화 종료 및 재개, 실제 보충 구간 처리, 배포 URL 검증.

## 처리 방식
1. 원본 바이트를 ArrayBuffer 형태로 IndexedDB에 저장하고 재생할 때 Blob을 복원한다. (WebKit의 Blob 직접 저장 실패 대응.) 녹화는 사용자가 정면을 지정한 뒤 시작하며, 명시적 마무리만 결과 화면으로 전환한다. 카메라/녹화 오류, 숨김은 완료 신호가 아니다.
2. Mediabunny VideoSampleSink가 모든 프레임을 표시 순서대로 해독한다. 프레임마다 시간·선명도·밝기·변화량·인접 프레임 2D 패치 대응을 기록한다. 패치 대응은 배경도 포함할 수 있으므로 제품 분할/포즈/3D 표면 대응이라고 부르지 않는다.
3. 48개의 **연속 프레임 전부**를 8×6 이미지 묶음으로 전송한다. 원본 프레임 번호와 시간이 붙는다. 빈 마지막 칸은 관찰 대상이 아니다. 특정 시간 간격의 사진 몇 장만 선택하는 경로가 아니다.
4. 각 구간의 처음·중간·마지막 원본 해상도 장면도 함께 제공해 작은 썸네일의 형태/구성 오인을 줄인다. 연속 프레임 전체 입력은 유지한다. AI가 구간 전체에서 발견한 부위·변화·부족 근거를 원본 프레임/좌표로 반환한다. 제품이 없는 구간을 배경 부품으로 등록하지 않는다.
5. 발견한 부위마다 원본 영상을 다시 해독해 해당 부위 크롭(최대 1024px)과 전체 프레임(최대 1280px)을 전송한다. 과거 비교 이미지는 현재 관찰 이미지와 명시적으로 분리하고, 이전 부위 이미지와 비교해 동일 부위/상태인지 검증한다. 이 단계의 대표 프레임은 세부 확인용이며 전체 시간축 입력을 대체하지 않는다.
6. 모든 관찰은 원본 clip/frame/time/box와 연결된다. `closed/open/fixed/unknown`은 물리적 구성 상태다. 흐림·가림 등의 품질과 분리한다. 아직 보이지 않은 내부는 예상 상태 `open`의 미관찰 가설로 남긴다.
7. 같은 부위/상태의 선명하고 대응이 확인된 서로 다른 시점 2개(같은 클립에서는 0.4초 이상)가 보충 근거가 된다. 다른 면·다른 상태·모델 응답에서 항목이 사라짐으로 해결하지 않는다. 이미 충분한 근거가 있는 부위의 일시적 흐림은 새 보충 요구로 만들지 않는다.
8. 보충 촬영은 기존 기록에 클립을 추가한다. 선택한 부족 항목을 우선 전달하고 전체 시간축을 동일하게 분석한다. 원본·중간 결과·세부 검증을 저장하므로 실패한 구간을 재개할 수 있다.
9. 기획에는 모든 누적 관찰 텍스트와 시각·품질·상태·부족 항목을 `brief.videoContext`로 전달한다. 시각 기준을 위한 대표 사진(최대 24장)도 전달한다. 원본 동영상은 기기에 남는다.

## 완료의 의미와 한계
- 해독 프레임 수와 압축 패킷 수가 일치하고 처음/마지막 시간 범위를 포함해야 한다. 모든 구간과 세부 확인 ID가 완료돼야 전체 처리 완료다.
- **전체 시간구간 처리 완료는 360도 표면 확보, 3D 재구성 또는 모든 세부 의미의 무누락을 보증하지 않는다.** 영상에 없거나 가려진 면은 복원할 수 없다.
- LLM 입력은 원본 동영상 컨테이너 자체가 아니라 모든 프레임의 축소된 연속 묶음과 발견 부위 원본 크롭이다. 모델의 부위 발견·대응·텍스트 판독에는 오류 가능성이 있다. 전체 프레임을 보냈다는 사실과 모든 의미를 정확히 인식했다는 주장은 다르다.
- 한 영상 200MB/180초/12,000프레임, 누적 부위와 보충 항목 각 48개. 한 연속 구간의 의미 관찰은 최대 6개다. 한도를 넘으면 오류로 멈추며 영상 뒷부분을 조용히 버리지 않는다.
- 메모리·CPU·기기 저장 공간과 코덱 지원에 영향을 받는다. 분석은 여러 API 호출이므로 시간이 걸린다. 모바일 물리 기기별 성능·카메라 드라이버 검증은 브라우저 에뮬레이션과 별개다.
- 원본/결과는 기기 IndexedDB에 있다. 사이트 데이터 삭제나 브라우저 저장 공간 회수로 사라질 수 있으므로 원본/근거 내보내기를 제공한다.
- 데모 접근 코드 요구 없음. 기존 서버 OpenAI API 연결, `store:false`. API 키는 클라이언트에 보내지 않는다. 개인 검증 영상과 근거 파일은 `.vercelignore`의 artifacts 제외 규칙으로 배포하지 않는다.

## 2026-11-16 검증 결과

- 실제 제공 MOV: 원본 36,699,440바이트, 1080×1920, OpenCV 기준 1,169프레임/약 39.03초. 원본 파일은 변경하지 않았다.
- Chromium/Android 크기: 1,169/1,169프레임 해독, 25/25 연속 구간 완료, 번호 0..1168을 정확히 한 번씩 포함. 실제 OpenAI API로 모든 구간 및 부위 크롭 검증. 중간 모델의 잘못된 프레임 번호를 거절한 뒤 출력 스키마를 해당 구간 ID로 제한했고, 실제 완료된 18구간을 보존해 나머지 7구간부터 재개했다. 92.93초는 **재개 구간만**의 검사 시간으로 전체 처리 시간과 다르다.
- 실제 결과: 10개 부위/구성 관찰 항목, 114개 원본 근거. 28.8–32초 주변의 제품 화면 이탈과 33.6초 이후 열리는 구성 변화를 구분. 후반 열린 내부 및 내부 브랜드 표기를 발견하고 원본 해상도로 확인. 내부는 선명한 원본 근거 4개, 해당 미관찰 항목은 이후 구간의 독립된 근거 3개로 갱신. 힌지·측면·열린 걸쇠·시각 대응 공백 등 불확실성 4건은 열린 상태로 유지.
- 보충 흐름: 동일 원본에서 만든 실제 앞 48프레임 영상(닫힘)을 분석 → 내부 미관찰 선택 → 원본 33–39초의 179프레임 영상을 추가 → 총 227/227프레임·5/5구간 완료. 내부 항목에 1.6016/3.2032/4.8048/5.4054초의 4개 선명한 보충 근거를 연결. 영상 재촬영 시뮬레이션이 아니라 **실제 영상의 두 구간으로 검증한 입력/보충 흐름**이다.
- iPhone 13 WebKit 에뮬레이션: 실제 MOV 전체 1,169프레임 해독, 원본 바이트 보존, API 중단(검사에서 502 주입), 새로고침 후 미완료 구간 복원. 가로 넘침 및 브라우저 JS 오류 없음. WebKit의 Blob 직접 저장 실패를 재현한 뒤 원본 ArrayBuffer 저장으로 해결했다.
- 모바일 녹화: 실제 제공 영상을 카메라 대신 재생 스트림으로 공급. 사용자 종료 없는 MediaRecorder.stop과 document.hidden을 주입해 자동 결과 전환이 없음을 확인. 명시적 종료 후 실제 영상 Blob 저장, 일시정지·재개 통과. 사용자가 겪었던 특정 기기의 최초 오류 원인은 로그가 없어 확정하지 않았다.
- 기획 연결: 실제 완료 분석을 복원한 모바일 브라우저에서 버튼을 조작. 10개 항목·114개 근거 전체 텍스트/시간/상태와 대표 사진 8장 전달, `/prompt` 이동 및 영상 관찰 연결 표시 확인. 사진 8장이 전체 관찰을 대신하지 않는다.
- 관련 자동 검사 59개 통과. TypeScript 검사, 통합 앱과 촬영 데모 production build 통과.
- 시각 점검으로 보충 완료 항목에도 과거 미관찰 문구와 촬영 지시가 남던 표시를 수정했다. 현재 미완료 항목을 먼저 보여주고, 완료 항목은 새 근거 사진과 완료 설명을 보여준다.
- **미실시:** 물리적 iPhone/Android 카메라·저메모리 환경의 장시간 실기기 테스트, 다양한 제품군의 정량 인식률 평가, 3D 표면 완전성 검증. 모델 관찰은 검수 가능한 추정이며 무오류 보증이 아니다.

검증 결과 JSON/스크린샷은 `artifacts/video-evidence/`에만 보관한다. 이 경로는 Git 및 Vercel 배포에서 제외된다.

## MVP 진행 조건 조정 (2026-11-16)
- 전체 구간 완료는 분석 감사 기준으로 유지하되, 기획 이동의 필수 조건에서 분리했다. 기준 정면 또는 관찰 사진이 있으면 ‘현재 자료로 기획하기’로 진행할 수 있다.
- 진행 중에는 AbortController로 분석을 멈추고 진행 작업의 정리가 끝난 뒤 최신 관찰을 전달한다. 원본/구간 결과는 보존한다. 미완료 여부·처리 구간 수·대기 영상과 미확인 근거를 기획에 함께 전달하며 완료로 표시하지 않는다.
- 분석 중의 보충 버튼도 ‘분석 멈추고 보충하기’로 사용할 수 있다. 분석 정리 중에는 이중 이동/새 촬영을 잠가 상태 충돌을 방지한다.
- 제품이 화면에 없는 경우와 같은 제품인지 확신하지 못한 경우를 다른 문구로 표시한다. 대응 불확실성은 실제 제품 부위 목록/대표 사진 선택에서 제외한다.
- 추가 제공 영상(video-1.mp4, 46.05초/1,381프레임)은 로컬에서 해독하고 모바일 iPhone 크기 브라우저에서 응답 지연을 주입해 전환을 검사한다. 이 검사는 외부 AI에 추가 영상을 보내지 않으며 인식 정확도 검증과 구별한다.
