# 기준 정면·회전 안내와 촬영 중단 복구

2026-11-16. 현재 구현은 `app/capture/orbit.tsx`이며 모바일 조작을 우선한다.

## 사용 흐름

1. 카메라를 연다. 이 단계에서는 녹화하거나 AI로 사진을 보내지 않는다.
2. 사용자가 기준 정면을 찍고 사진의 위쪽을 확인한다. 회전할 화면 방향(오른쪽/왼쪽)을 선택한 뒤 확정한다. 정면이 없는 제품도 이번 촬영의 기준면을 지정한다.
3. 기준 사진을 보관하고 녹화·분석을 시작한다. 기준 정면이 돌아갈 화면 방향을 화살표와 문장으로 유지한다. LLM의 자유 문구는 회전 지시를 덮어쓰지 않는다.
4. 브라우저의 이미지 변화·노출·선명도 검사로 속도 피드백을 표시한다. 물체의 실제 각속도나 회전 완료 측정은 아니다. 사용자가 한 바퀴를 돌렸다고 확인하면 보충 단계로 전환한다.
5. 가림/흐림 부위가 식별되면 해당 관찰 사진에 정규화 좌표 상자를 표시한다. 확대해서 확인할 수 있다. 라이브 영상의 현재 위치를 추적하는 표시가 아니다. 위치 미확인·보지 못한 영역에는 상자를 지어내지 않는다.
6. ‘촬영 마치고 확인’을 직접 눌러야 검토로 이동한다. 첫 기준 사진은 AI가 실패해도 보존한다.

## 자동 전환 문제

사용자의 당시 실행 로그가 없어 정확한 단일 원인은 확정하지 못했다. 기존 구현에서 다음 경로가 모두 `stop()`을 호출하며 즉시 검토로 이동한 사실을 확인했다: AI 요청 오류/26초 타임아웃, 90초 경과, 분석 횟수 한도, 카메라 트랙 종료, 녹화 오류·종료·용량 한도.

- AI 오류, 타임아웃, 오프라인, 화면 숨김, 카메라 중단: 촬영 화면에서 일시정지하고 원인 및 계속 촬영 버튼을 표시.
- 90초 또는 구간 분석 18회: 일시정지 후 사용자가 계속할지 결정. 세션 총 54회 이후에는 직접 종료해 자료 확인.
- 영상 오류/30MiB 한도: 영상만 마무리하고 사진 수집 지속. 이전 영상 보존. 카메라 재연결 후에는 사진 수집으로 이어짐.
- 중단/종료 후 늦은 응답은 요청 세대 번호로 무시. 재개 중 다시 중단된 경우 이전 재개 처리가 새 중단 상태를 해제하지 않음.
- manifest v7에 기준 사진, 방향, 품질 타임라인, 중단·재개 사유 기록. 검토 화면에도 ‘촬영 중 일어난 일’ 표시.

## 검증

- Node 테스트 40개 통과. 기준 사진·방향 전달, 좌표 검증, 속도 상태, 동일 부위 보충 비교, 기존 기획 연결 회귀 포함.
- 통합 앱 타입 검사·변경 파일 ESLint·production build 통과.
- `scripts/check-capture-mobile.mjs`: Chromium(Chrome) 및 Playwright WebKit 27.2, 모바일 터치 에뮬레이션. 390×844 기본, 320×568 / 360×740 / 430×932 / 844×390 레이아웃 검사. 합성 캔버스 미디어 스트림, 모의 AI 응답 사용.
- 두 브라우저에서 기준 확정 전 요청 없음, 왼쪽 회전 유지, 좌표 표시·확대, 보충 단계, 모델의 review 응답에도 촬영 유지, 502/타임아웃/오프라인/화면 숨김/카메라 종료 복구, 90초 일시정지, 터치 버튼, 명시적 종료, 녹화기 오류, 종료 후 늦은 응답, 권한 거부 후 재시도 표시 확인.
- 증거: `artifacts/capture-mobile/results.json` 및 같은 폴더의 PNG.
- 실제 OpenAI 호출: 합성 제품 기준 사진 + 같은 현재 사진으로 HTTP 200, gpt-5.4-mini, sameProduct=yes, inspection.box=null 응답 확인. 기준 사진 전달과 신규 구조화 응답 연결을 확인한 것이며 부위 인식 정확도 검증은 아님.
- 실물 안경케이스, 실제 iPhone/Android 카메라·열·메모리·OS 백그라운드 제한은 미검증. WebKit 에뮬레이션은 실제 iPhone Safari 검증과 동일하지 않다.

검사 재실행에는 Playwright 및 WebKit 설치가 필요하다. `CAPTURE_TEST_URL`, `PLAYWRIGHT_MODULE`, `CHROME_PATH`로 서버와 설치 위치를 지정할 수 있다. 브라우저 테스트는 기존 사용자의 저장 자료를 건드리지 않는 새 컨텍스트에서 실행한다.

촬영 전용 배포 소스는 `node scripts/package-capture-demo.mjs`로 현재 엔진에서 생성한다. 통합 앱의 기획 이동 버튼만 제외하고 엔진·모바일 화면은 공유한다.
